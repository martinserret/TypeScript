WHAT IS WEBPACK & WHY DO WE NEED IT
////////////////////////////////////////////

The problem we have using our previous setup is that we a have a bunch of HTTP requests (in the tab "Network" in your browser). Theses files are relatively small but there are a lot of HTTP requests.
The problem is that each requests takes time to download the files and has a base duration (the browser makes the request and send it, then we have the work on the server which serves the file, etc.).
Deploying that kind of app on the web, with many requests can really introduce a lot of latency and slow down the project.

Webpack is a solution to reduce that amount of HTTP requests. Webpack bundle our files together. "Build Orchestration" tool : https://webpack.js.org/

You can write codes split up across multiple files but Webpack then takes all these files and bundles them together. It will also optimize our code and it also allows us to add more build steps, minified code, more build tools.

To install Webpack: npm install --save-dev webpack webpack-cli webpack-dev-server typescript ts-loader 

- webpack: heart of this entire setup. Toll that allows us to plug in certain functionalities to bundle and transform our code.
- webpack-cli: allows to run webpack commands
- webpack-dev-server: built in development server that watches our files for changes and automatically triggers webpack to recompile when something changes and which auto serves our page
- typescript: good practice to auto install a copy of Typescript per project (for the version)
- ts-loader: works with webpack and tells it how to convert Typescript code to Javascript


IMPORTANT: in our Typescript files, remove all ".js" at the end of the imports file


in webpack.config.js:
- module: in the end is just a file. We tell Webpack how to work with different file types it finds (ts, js, html, css, etc.). In our case: only TypeScript files.
- resolve: which file extensions Webpack should resolve. By default, it only resolves .js files, so we add .ts to it.
- devtool: tells webpack that there will be generated source maps. This is useful for debugging, as it allows you to see the original TypeScript code in the browser's developer tools instead of the compiled JavaScript code.
- devServer: configuration for the development server. It serves files from the current directory (__dirname) and allows you to access your application in the browser during development.

To use webpack, add a script in package.json: "build": "webpack"
